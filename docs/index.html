TeamTalk Bot Documentation

This bot automates administrative workflows for a TeamTalk 5 server. It provides channel creation wizards, user registration sessions, moderation tools, abuse tracking, badword enforcement, and maintenance utilities such as auto-cleaning inactive channels.

Quick Start

  1. Install Python 3.12+ on the host where the TeamTalk server is reachable.
  2. Place libTeamTalk5.so (Linux/WSL) or TeamTalk5.dll (Windows) inside TeamTalk_DLL/.
  3. Run the bot once; it will create config.json populated with defaults.
  4. Edit config.json to provide server credentials, channel defaults, and policies.
  5. Run the bot: 
    python3 main.py
  6. Monitor output/logs, then interact with the bot in TeamTalk via private messages.

Configuration Overview (config.json)

Below is a mirror of the inline comments that used to live in config.py.

Server & Credentials

  • SERVER_HOST, TCP_PORT, UDP_PORT: address/ports of your TeamTalk server.
  • SERVER_ENCRYPTION_ENABLED: set true if the TeamTalk server requires TLS/DTLS.
  • TLS_CERTIFICATE_FILE, TLS_PRIVATE_KEY_FILE, TLS_CA_FILE, TLS_CA_DIR, TLS_VERIFY_SERVER, TLS_VERIFY_CLIENT_ONCE, TLS_VERIFY_DEPTH: optional certificate paths and verification controls when TLS is enabled.
  • TEAMTALK_LICENSE_NAME, TEAMTALK_LICENSE_KEY: SDK license credentials provided by BearWare.dk. Both must be filled or the bot runs in demo mode.
  • ADMIN_USERNAME, ADMIN_PASSWORD: admin account the bot uses to log in and perform privileged actions.

Bot Identity

  • BOT_NICKNAME, CLIENT_NAME: values shown to other users.
  • BOT_DEFAULT_STATUS_MESSAGE, BOT_DEFAULT_STATUS_MODE: status text and availability mode (0=Available, 1=Away, 2=Question).

User Rights Template

DEFAULT_USER_RIGHTS maps each UserRight enum name to "yes"/"no". This template is applied to every account created via the registration wizard.

Channel Defaults

  • LOGIN_CHANNEL_PATH/LOGIN_CHANNEL_PASSWORD: lobby the bot joins after login.
  • CREATE_CHANNEL_PARENT_PATH: base path for new channels ("" or "/" means root).
  • CHANNEL_DEFAULTS: properties applied when creators choose default settings — includes max_users (0 locks channel), disk_quota_mb (0 disables uploads), plus boolean flags (permanent, hidden, no_interruptions, classroom, operator_receive_only, no_voice_activation, no_recording).

Audio Defaults

AUDIO_DEFAULTS controls Opus characteristics when users accept the defaults:

  • application: "voip" or "music".
  • sample_rate: one of 8000/12000/16000/24000/48000.
  • channels: "mono" or "stereo".
  • bitrate_kbps: choose from 16/32/64/128/256/320.
  • transmit_interval_ms: multiples of 20 between 20–500.
  • frame_size_ms: multiples of 20 up to 120.
  • Booleans variable_bitrate, ignore_silence (maps to Opus DTX), fixed_audio_volume (EnableFixedAudioLevel) round out the profile.

Channel Lifecycle

  • CHANNEL_INACTIVITY_TIMEOUT: object with value + unit (minutes/hours/days/weeks/months). Value <= 0 disables auto deletion.
  • CHANNEL_DELETION_WARNING_SECONDS: delay between warning message and deletion when only non-owners remain.

Channel Creation Rules

  • CHANNEL_CREATION_MAX_PER_USER: cap on concurrently owned channels (0 = unlimited).
  • CHANNEL_CREATION_LIMIT_MESSAGE: text sent when the limit is reached ({limit} placeholder available).
  • CHANNEL_CREATION_BLOCKED_USERNAMES: case-insensitive list of users who may never create channels.
  • CHANNEL_CREATION_BLOCKED_MESSAGE: response when a blocked user attempts creation.

Registration Policy

  • REGISTRATION_ALLOWED_USERNAMES: usernames (case-insensitive) that may request new accounts. Typically ["guest"] to limit spammers.
  • REGISTRATION_NOT_ALLOWED_MESSAGE: text sent when disallowed users attempt registration.
  • REGISTRATION_IP_LIMIT, REGISTRATION_IP_WINDOW_MINUTES, REGISTRATION_IP_LIMIT_MESSAGE: per-IP quota, window length, and message when quota is exceeded.

Abuse Throttling

  • ABUSE_LOGIN_COUNT, ABUSE_JOIN_COUNT, BADWORD_ABUSE_COUNT: events per key within ABUSE_WINDOW_SEC before escalation.
  • ABUSE_TEMP_BAN_MINUTES: temporary ban duration at stage 3.
  • ABUSE_LOGIN_WARNINGS, ABUSE_JOIN_WARNINGS, BADWORDS_WARNINGS: text templates shown at each stage (use {duration} placeholder for minutes).

Badword Enforcement

  • BADWORDS_ENABLED: master switch.
  • BADWORDS_INTERCEPT_TYPES: list of message types to inspect ("PRIVATE", "CHANNEL", "BROADCAST"). Include entries to enable inspection of those scopes.
  • BADWORDS_FILE: UTF-8 file storing one word per line (comma-separated values also supported). The bot writes new words here when admins use /bwa//bwd.
  • BADWORDS_IGNORE_ADMINS: skip enforcement for admin users when true.
  • BADWORDS_PROFILE_CHECK_ENABLED: when true, nicknames/status messages are scanned via moderation_utils.check_user_profile_badwords.

Reconnection & Event Loop

  • RECONNECT_MAX_ATTEMPTS: stop retrying after this many failed attempts (0 = unlimited). When limit reached, bot shuts down to avoid resource usage.
  • RECONNECT_RETRY_DELAY_SEC: delay between attempts.
  • EVENT_LOOP_WAIT_MS: polling wait passed to runEventLoop. Lower values react faster but use more CPU.
  • EVENT_LOOP_SLEEP_SEC: sleep inserted at the end of each loop iteration.

Logging

  • LOG_LEVEL: one of DEBUG/INFO/WARNING/ERROR/CRITICAL.
  • LOG_FORMAT, LOG_DATE_FORMAT: standard logging format strings.

Interactive Wizards

Registration Wizard (/ru)

  1. User runs /ru (optionally with a username).
  2. Bot validates username format, checks availability via doListUserAccounts.
  3. Once available, bot prompts for password (strong policy enforced) and full name.
  4. On success, bot submits doNewUserAccount, records IP throttling metadata, and confirms completion.

Channel Wizard (/rc)

  1. User runs /rc <name>; bot ensures no slashes or leading symbols.
  2. Prompts: channel password, topic, operator password, property overrides (max users, flags), default usage choice.
  3. Audio questionnaire (or default) includes application, sample rate, mono/stereo, bitrate, VBR, ignore silence, transmit interval, frame size, fixed volume.
  4. Bot issues doMakeChannel, tracks ownership, announces TTL if auto-cleanup enabled.

Automatic Channel Cleanup

When CHANNEL_INACTIVITY_TIMEOUT is enabled, channels created through the bot are periodically checked:

  • Owner presence refreshes last_active_at.
  • If TTL expires and only non-owners are present, bot moves into the channel, sends a warning message, returns to its original channel, and schedules deletion after CHANNEL_DELETION_WARNING_SECONDS.
  • If the owner rejoins before the timer elapses, deletion is cancelled; otherwise the bot removes the channel.

Badword Management

Badwords live in the UTF-8 file configured via BADWORDS_FILE. The bot loads the file at startup and keeps it in sync whenever /bwa or /bwd is used. Filters operate on channel, broadcast, private, and profile text depending on configuration.

Abuse Tracking

The AbuseTracker monitors login/join/badword events per IP or user. Thresholds per kind are configurable. Each escalation clears the event bucket and steps through warnings, kicks, and auto-temp bans as defined in config.py.

Running & Deployment

  • Run under a dedicated system user. Consider systemd or a Windows service for production.
  • Monitor logs through standard output or redirect to files; logging is configured before bot initialization.
  • On Linux/WSL ensure libTeamTalk5.so is in $PWD or added to LD_LIBRARY_PATH.
  • Use python3 -m compileall or run unit-style smoke tests after refactors to ensure no syntax regressions.

Maintenance Guidelines

SDK Boundary: Never edit files inside TeamTalkPy/ or TeamTalk_DLL/. Treat them as vendor dependencies.
  • All Python files must remain UTF-8 encoded and PEP 8 compliant (use ruff or flake8 if desired).
  • Add docstrings for every new module, class, and function—mirror existing style.
  • Keep configuration-driven behaviors documented in docs/index.html and CHANGELOG.md.
  • When adding commands, update help_texts.py and command_handler.py in tandem.
  • Do not share business logic between wizards and command handlers through global state; prefer helper modules.
  • Always update __version__ in version.py and add release notes to CHANGELOG.md.
